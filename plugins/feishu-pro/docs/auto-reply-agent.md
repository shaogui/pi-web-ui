# 自动回复 2.0：前置分析 → 在允许的范围内把事办了

0.17.0 起，自动回复不再只是「写一句话回过去」，而是一条**受限的执行链**（0.18.0 起同一套链同时覆盖私聊与群聊）：
插件做触发与前置分析，宿主 agent 跑流程，插件负责唯一出口与留痕。

```
dm-watch 轮询出新消息
  └─ matchAutoReply        范围（白名单 / 全部私聊 / 全部群组）/ 群 @我 / 冷却 / 限频 / 陈旧
       └─ inbox.claim      同一条消息只处理一次（跨重启）
            └─ matchRisk   风险词表（ignore / block / overreach / review）
                 └─ 前置分析 host.llm.complete（无工具、20s 超时，只回 JSON）
                      ├─ send      直接发：一次小补全就答完，不起 agent
                      ├─ compose   派一轮「只写正文」（旧行为，triage 不可用时的兜底）
                      ├─ work      派一轮可动手：scratch cwd + 只读素材目录
                      ├─ escalate  不发：通知我 + 落一条待办
                      └─ ignore    不发，也不打扰
```

**会话隔离**：每个 `chatId` 一个伪客户端（`plugin:feishu-pro:auto-<chatId>` / `auto-work-<chatId>`）。
宿主在拿不到 `conversationId` 时用的是该伪客户端的「当前活动会话」，共用账号会让第二个会话的第一条消息
落进第一个会话（上下文串台，work 还会因 cwd 不同被拒）；按 chatId 分账号是最省事的隔离方式。

## 1. 为什么把「要不要动手」放到 agent 之前

让模型在运行中自己决定「要不要调工具」，等于把成本与风险都交给一次没人看着的运行。
前置分析把这件事变回一个**可解释的判定**：

| 好处   | 具体表现                                                                   |
| ------ | -------------------------------------------------------------------------- |
| 便宜   | 绝大多数消息（寒暄 / 已知事实）一次 `llm.complete` 就答完，不烧 agent run  |
| 可控   | 高风险词命中时**连模型都不问**，直接转人工                                 |
| 可审计 | 每条消息都有 `route + why`，面板里能看到「为什么没回 / 为什么动手」        |
| 可降级 | 分析失败、超时、非 JSON → 一律退回 `compose`，绝不让失败的分类变成一次执行 |

## 2. 四个路由

| 路由       | 触发                                               | 行为                                         | 成本              |
| ---------- | -------------------------------------------------- | -------------------------------------------- | ----------------- |
| `send`     | 模型给了可直接发的正文                             | 直接走发送通道                               | 1 次小补全        |
| `compose`  | 分析不可用 / 模型没给正文                          | 派一轮"只写正文"（工具仍在，提示词禁止使用） | 1 轮 agent        |
| `work`     | 需要查资料 / 动手，且 `workEnabled=true`           | 派一轮可动手，cwd 是沙盒                     | 1 轮 agent + 工具 |
| `escalate` | 风险词 block/overreach、模型判定需人确认、动手超额 | 不发消息；通知 + 可选建待办                  | 0–1 次小补全      |
| `ignore`   | 广告 / 系统消息                                    | 不发，也不通知                               | 0–1 次小补全      |

**优先级**：风险词 > 模型建议。block/overreach 时模型说什么都不算；反过来，模型自评 `risk=high` 也直接转人工（词表没覆盖到的风险同样算风险）。

## 3. 能力边界：两个目录 + 一条铁律

| 位置                                  | 谁写   | 谁读       | 对外                                       |
| ------------------------------------- | ------ | ---------- | ------------------------------------------ |
| `<dataDir>/feishu-pro/runs/<chatId>/` | agent  | agent      | **否**（私有沙盒，按会话复用，多轮能续上） |
| 「素材目录」（设置里配，全局一个）    | **人** | agent 只读 | 是（可摘要 / 可引用链接）                  |

- 素材目录在保存时校验：必须存在、必须是目录，且不能是 `/`、用户主目录、数据目录、工作区根。
- 写素材目录会被「工作区外写入」审批规则挡住（无人值守下等 120s 再拒），所以提示词必须提前说明只读。
- **唯一出口**：发送只由插件完成；`work` 运行里 agent 被明令禁止 `im_send`。
  P0 若检测到 agent 自己发了（`feishu_pro action=im_send` 且未报错），插件**跳过自己的回包**并记 `sentBy=agent` ——
  宁可少发一次，不可双发。P1 会在宿主侧把这个动作直接禁掉。

## 4. 风险词表（`lib/risk-lexicon.mjs`）

| 档位        | 例子                                       | 动作                              |
| ----------- | ------------------------------------------ | --------------------------------- |
| `ignore`    | 推广 / 广告 / 刷单 / 群公告 / 系统消息     | 静默                              |
| `block`     | 转账、发票、合同、报价、薪资、验证码、涉密 | 转人工（通知 + 待办）             |
| `overreach` | 拉人进群、改群设置、代发代付、导出成员名单 | 转人工                            |
| `review`    | 时间承诺、进度排期、价格询问、他人联系方式 | 可回，但不许 work、不许给具体数字 |

调词表的三个旋钮：`terms`（命中任一）、`except`（命中即整条跳过，治「合同模板」）、`withAny`（同时出现才算，治「明天 + 交付」）。
优先级 `ignore → block → overreach → review` 是刻意的：广告里出现「最低价」应该静默，而不是升级成转人工把我吵醒。

## 5. 提示词契约（`buildTriagePrompt` / `buildWorkPrompt`）

- **先理解诉求**：前置分析先回答「对方真正要账号所有者做什么」，`intent` 放在 JSON 第一位，
  再选路由；不允许只按关键词匹配。
- **承接动作、不反抛决定**：开通 / 申请 / 审批 / 给权限这类请求，默认「我来办 + 下一步」，
  不能反问对方「你想要什么账号和密码」。最多问一个只有对方才知道的事实（邮箱 / 项目名）。
- **素材目录只读、scratch 可写**：写清绝对路径，避免模型靠猜。
- **禁止自己发消息**：`no feishu_pro action=im_send — the plugin delivers your FINAL text`。
- **输出 `FINAL:`**：只发标记之后的正文；没有标记时，短正文（≤1200 字）仍可作为回复，长文本视为工作笔记不发。
- **不许承诺**：价格、日期、交付物一律不给具体值；不确定就说不确定。
  但「承接一件常规的事」不算承诺（它与「编造具体数字」是两件事）。
- **我的背景**：设置里的 `ownerProfile` 会贴进 triage / compose / work 三处提示词，
  让模型知道账号所有者的角色与能拍板的事。

## 6. 失败语义

| 情况                       | 行为                                                                |
| -------------------------- | ------------------------------------------------------------------- |
| 前置分析失败 / 超时        | 降级 `compose`（旧行为）；work 永不因分类失败而启动                 |
| 运行超时（默认 120s）      | `host.abortRun` 中止 → 发一句安全回执（"收到，我确认一下再回你。"） |
| 运行只有工具调用、没有正文 | 同上，发安全回执，不静默                                            |
| 发送失败                   | 不重试；记录 + 通知（与手发消息同一条铁律）                         |
| 重启 / 崩溃                | `host.inbox` 幂等键挡住重复处理（副作用最多一次）                   |
| 本小时动手超额             | 转人工（通知 + 待办），不再起运行                                   |

## 7. 配置（面板「③ 自动问答」）

**会话范围**（准入的第一道闸，三选一或叠加，全空 = 谁都不回）：

| 字段               | 默认      | 说明                                                                 |
| ------------------ | --------- | -------------------------------------------------------------------- |
| `chatIds`          | 空        | 指定会话（`oc_…`）：显式指定优先，群也不受「只回 @我」约束           |
| `allDms`           | **false** | 全部私聊：轮询到的单聊都纳入（需「消息同步」的「私聊（自动发现）」） |
| `allGroups`        | **false** | 全部群组：轮询到的群都纳入（需「消息同步」的「群聊（自动发现）」）   |
| `groupMentionOnly` | `true`    | 「全部群组」范围内只回 **@我** 的消息；关掉才逐条回                  |

范围能不能真的收到消息，取决于 dm-watch 在轮询哪类会话：`allDms` 要 `autoDiscover`、`allGroups` 要
`syncGroups`，且受单轮预算（30 私聊 / 20 群，按最近活跃截断）限制。面板会把「勾了但不生效」就地写出来，
`GET /auto/state` 的 `sync` 字段是这层提示的数据源（`enabled` / `autoDiscover` / `syncGroups` / `p2p` / `groups` / `budget` / `sample`）。

其余字段：

| 字段             | 默认      | 说明                                                                   |
| ---------------- | --------- | ---------------------------------------------------------------------- |
| `triage`         | `true`    | 开 = 每条消息先做一次前置分析                                          |
| `workEnabled`    | **false** | 允许 agent 动手                                                        |
| `maxWorkPerHour` | 3         | 动手单独限频（0 = 不限）                                               |
| `runTimeoutSec`  | 120       | 单轮上限（0 = 不限）                                                   |
| `libraryDir`     | 空        | 对外素材目录（只读）                                                   |
| `ownerProfile`   | 空        | 我的背景（角色 / 能拍板的事 / 常用口径，≤1000 字）；会话内 AI 回复共用 |
| `escalateTodo`   | `true`    | 转人工时落一条待办（ref = 消息 id，不会重复）                          |
| `redact`         | `true`    | 出站脱敏：手机号 / 邮箱 / 证件 / 卡号 / 密钥 / 本机路径                |
